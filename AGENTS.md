# Правила для AI-агентов

## Назначение

Репозиторий хранит общую архитектуру, карту репозиториев, план поставки и решения Portable Agent.
Кода отдельных сервисов здесь быть не должно.

## Границы

- Не добавляй сюда модуль сервиса или общую доменную библиотеку.
- Не придумывай правила бизнеса без решения владельца продукта.
- Решение для одного сервиса храни в его репе; решение для нескольких реп — здесь как ADR.
- Не описывай запланированный репозиторий как уже созданный.

## Структура

- `docs/architecture/` — общая архитектура и границы.
- `docs/adr/` — решения, которые влияют на несколько реп.
- `docs/delivery/` — порядок этапов.
- `catalog/` — карта сервисов и репозиториев.
- `website/` — публичный сайт Docusaurus.
- `catalog-info.yaml` и `mkdocs.yml` — данные для Backstage и TechDocs.

## Правила изменений

1. Пиши по-русски и короткими предложениями.
2. Используй простой английский в именах: `ActionService`, `ActionController`, `ActionRepository`.
3. Для поведения придерживайся TDD: тест → минимальный код → улучшение.
4. Не вводи новую технологию без задачи и ADR.
5. Обновляй карту репозиториев и статус только по проверенным фактам.
6. Обновляй документацию вместе с кодом, который она описывает.
7. Перед завершением запусти доступные проверки.
